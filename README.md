# api_final_yatube

## Описание
API социальной сети с возможностью публикации, комментирования постов и подписки на авторов

## Технологии
Python 3.9
Django 3.2.16
Django REST framework 3.12.4

## Как запустить проект:

Клонируйте репозиторий:
```git clone https://github.com/lavralex/api_final_yatube.git```

Перейдите в него в командной строке:
``` cd api_final_yatube```

Cоздайте виртуальное окружение:

```python3 -m venv venv```

Активируйте виртуальное окружение:

* для Linux/macOS

```source venv/bin/activate```

* для windows

```source env/scripts/activate```

Обновите pip:

```python3 -m pip install --upgrade pip```

Установите зависимости из requirements.txt:

```pip install -r requirements.txt```

Выполните миграции:

```python3 manage.py migrate```

Запустите проект:

```python3 manage.py runserver```

## Как пользоваться

### регистрация

Для регистарии нужно отправить POST запрос на ```http://127.0.0.1:8000/api/v1/jwt/create/```

передав данные типа:
{
"username": "string",
"password": "string"
}
в ответ будут получены 2 токена
{
    "refresh": "данные для обновления токена",
    "access": "токен доступа"
}

### использование токенов
перед токеном нужно поставить ключевое слово Bearer
получившуюся конструкцию нужно передавать в заголовке запроса, в поле Authorization

### Обновление токена
В поле Authorization нужно указать refresh токен
и отправить POST запрос на ```http://127.0.0.1:8000/api/v1/jwt/refresh/```
и получите ответ типа:
{
"access": "string"
}

### Проверка токена
для проверки токена отправте POST запрос на ```http://127.0.0.1:8000/api/v1/jwt/verify/```
и получите ответ типа:
{
"token": [
"Обязательное поле."
]
}

### Подписки
работа с подписками ведется по адресу ```http://127.0.0.1:8000/api/v1/follow/```
при POST запросе вы подпишитесь на указанного вами пользователя 
пример запроса:
{
"following": "string"
}

при GET запросе вы получите список своих подписок

### Сообщества
работа с сообществами ведется по адресу ```http://127.0.0.1:8000/api/v1/groups/```
при GET запросе вы получите список доступных сообществ 
пример запроса:
[
  {
    "id": 0,
    "title": "string",
    "slug": "string",
    "description": "string"
  }
]

при при GET запросе и указании id (прим: ```http://127.0.0.1:8000/api/v1/groups/{id}/```)
вы получите информацию о сообществе

### Публикации
работа с публикациями ведется по адресу ```http://127.0.0.1:8000/api/v1/posts/```
при GET запросе вы получите список всех публикаций. При указании параметров limit и offset выдача должна работать с пагинацией.
пример:
{
"count": 123,
"next": "http://api.example.org/accounts/?offset=400&limit=100",
"previous": "http://api.example.org/accounts/?offset=200&limit=100",
"results": [
{}
]
}

при POST запросе вы опубликуете пост
пример:
{
"text": "string",
"image": "string",
"group": 0
}

работа с конкретной публикацией ведется по адресу ```http://127.0.0.1:8000/api/v1/posts/{id}/```
где id номер интересующей вас публикации

при GET запросе вы получите данные публикации
пример:
{
"id": 0,
"author": "string",
"text": "string",
"pub_date": "2019-08-24T14:15:22Z",
"image": "string",
"group": 0
}

при PUT запросе вы обновите публикацию
пример:
{
"text": "string",
"image": "string",
"group": 0
}

при PATCH запросе вы частично обновите публикацию, изменять все поля не нужно
пример:
{
"text": "string",
"image": "string",
"group": 0
}

при DELETE запросе вы удалите публикацию

### Коментарии

работа с коментариями публикации ведется по адресу ```http://127.0.0.1:8000/api/v1/posts/{post_id}/comments/```
post_id номер интересующей вас публикации 

при GET запросе вы получите все комментарии к публикации.
пример:
[
{
"id": 0,
"author": "string",
"text": "string",
"created": "2019-08-24T14:15:22Z",
"post": 0
}
]

при POST запросе вы опубликуете комментарий к публикации.
пример:
{
"text": "string",
}

работа с конкретным коментарияем публикации ведется по адресу ```http://127.0.0.1:8000/api/v1/posts/{post_id}/comments/{id}/```
post_id номер интересующей вас публикации
id номер интересующего вас комментария

при GET запросе вы получите данные комментаря.
пример:
{
"id": 0,
"author": "string",
"text": "string",
"created": "2019-08-24T14:15:22Z",
"post": 0
}

при PUT и PATCH запросе вы обновите комментарий.
пример:
{
"text": "string"
}

при DELETE запросе вы удалите комментарий.
